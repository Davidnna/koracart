# KoraCart

**Many sellers. One seamless marketplace.**

KoraCart is a cloud-first, multi-vendor e-commerce platform built with React, Django REST Framework and Neon PostgreSQL.

## Architecture

- `frontend/`: React + Vite + TypeScript + Tailwind CSS
- `backend/`: Django + Django REST Framework
- Database: Neon PostgreSQL
- Frontend hosting: Cloudflare Pages (global CDN)
- Backend hosting: Render (Frankfurt region)

## Initial milestone

This repository contains the branded application foundation:
- Responsive KoraCart storefront landing page
- Django REST API health endpoint
- Environment-based configuration
- Render Blueprint configuration
- GitHub Actions frontend and backend checks

Marketplace features (authentication, vendor onboarding, catalogue, cart, checkout, Paystack, order tracking and Nylas email) will be delivered incrementally.

## Deployment

### Backend on Render

The root `render.yaml` defines the KoraCart API service:
- Branch: `main`
- Region: Frankfurt
- Initial compute plan: Free
- Root directory: `backend`
- Build command: `bash build.sh`
- Start command: `gunicorn config.wsgi:application`
- Health check: `/api/health/`
- Automatic deploys: only after GitHub checks pass

The free Render web service is suitable for initial staging and project testing, not a production service with continuous availability. It spins down after 15 minutes without inbound traffic and can take about one minute to wake up. It also does not provide dashboard Shell access. Upgrade to a paid always-on service before relying on the platform for a live business or time-sensitive demonstration.

Set these environment variables in Render:
- `DATABASE_URL`: Neon pooled PostgreSQL connection string for normal application traffic
- `MIGRATION_DATABASE_URL`: Neon direct PostgreSQL connection string for Django migrations
- `DJANGO_ALLOWED_HOSTS`: the Render service hostname
- `CORS_ALLOWED_ORIGINS`: the deployed Cloudflare Pages origin
- `CSRF_TRUSTED_ORIGINS`: the deployed Cloudflare Pages origin

`DJANGO_SECRET_KEY` is generated by Render. Keep all credentials out of GitHub.

### Neon PostgreSQL

Create the Neon project in AWS Europe (Frankfurt), `aws-eu-central-1`, to keep the database in the same region as the Render backend. Neon project regions cannot be changed after creation.

Use the Neon Console's Connect dialog to retrieve two connection strings for the same branch, database and role:
- Pooled connection string (hostname contains `-pooler`) → Render `DATABASE_URL`
- Direct connection string (hostname does not contain `-pooler`) → Render `MIGRATION_DATABASE_URL`

Keep `sslmode=require` in both connection strings. Do not put either connection string in GitHub or send it in chat.

### Frontend on Cloudflare Pages

Create a Pages project connected to this repository:
- Production branch: `main`
- Root directory: `frontend`
- Build command: `npm run build`
- Build output directory: `dist`
- Environment variable: `VITE_API_BASE_URL=https://YOUR-RENDER-SERVICE.onrender.com/api`

Cloudflare Pages serves static assets through its global network. Add the final Pages origin to the backend's CORS and CSRF trusted-origin environment variables in Render.

## Environment variables

See `backend/.env.example` and `frontend/.env.example`. Never commit real credentials, API keys or database URLs.

## Initial admin account

The initial scaffold does not create an administrator account or ship a default password. We will implement a controlled, one-time administrator bootstrap mechanism before the admin dashboard milestone. Do not add a default administrator password to source code.

## Important

The initial release is the deployment foundation, not the completed marketplace. Payment, email, vendor and order workflows must be implemented and tested in later milestones before KoraCart is used for real transactions.
